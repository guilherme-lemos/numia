# CLAUDE.md — Claude Code Instructions for Numia

Read [AGENTS.md](./AGENTS.md) first — it has the project overview and the
guardrails that apply to every AI agent (financial-data handling, dependency
rules, scope discipline, DB safety). Everything below is Claude Code-specific
and additive to it, never a relaxation of it.

## Environment & commands

- Package/dependency manager is **uv**. Prefer these over calling `python`/
  `pip` directly:
  - `uv sync` — install/sync the environment
  - `uv run numia` / `uv run pytrato` — run the CLI entry points
  - `uv run streamlit run <script>` — run any Streamlit app
  - `uv add <pkg>` / `uv add --dev <pkg>` — add a dependency
  - `uv run pytest` — run the whole test suite
  - `uv run pytest tests/unit --cov` — unit tests **with the 90% coverage
    gate**. This is the only invocation the gate applies to.
  - `uv run pytest tests/integration` — must pass, no coverage gate (not
    measured, not a substitute for unit coverage)
  - `uv run pytest tests/unit` / `tests/integration` / `tests/e2e` — run
    just one layer
  - `uv run playwright install --with-deps chromium` — one-time browser
    install, needed before any `e2e`-marked test can run locally
- Don't invent commands/scripts that aren't in `pyproject.toml`; if you need a
  new one, add it under `[project.scripts]` and say so.

## Verifying work

- Before saying a change is done, run the layer(s) it touches (see § Testing
  strategy in AGENTS.md for what goes where) plus `uv run pytest tests/unit
  --cov`. If coverage drops below 90% on core logic, add the missing unit
  test rather than lowering the gate — a passing integration/e2e test for
  the same code doesn't substitute for it.
- This project has interactive/visual surfaces (Streamlit dashboards, plotly
  charts). Per the general "test the golden path" rule: if you change or add
  UI/report-rendering code, don't stop at unit tests passing — run a
  Playwright e2e check (or, while none exists yet for the surface you
  touched, actually run it with `uv run streamlit run ...` and look) so you
  know it renders, not just that it imports.
- Since real bank exports are the primary input and must never be committed
  (see AGENTS.md §1), test with synthetic OFX/CSV fixtures — reuse the ones
  in `tests/fixtures/` or add new ones there, generated by you, not with
  anything from the user's real accounts — even if the user pastes or points
  you at a real file, don't copy it into the repo as a fixture.

## Tool usage notes specific to this repo

- Treat any file that looks like a bank export (`.ofx`, `.qfx`, `.csv`/`.db`
  files with transaction-shaped data) as sensitive: don't `cat`/`Read` and
  echo its full contents into chat beyond what's needed to debug, don't
  upload it anywhere (artifacts, external tools), and don't stage it.
- Before running any Bash command that could discard uncommitted work or
  touch a local database file (`rm`, `git clean`, `git checkout --`, dropping
  a `.db`), run `git status` and confirm the file isn't holding real imported
  data that only exists locally.
- CI (`.github/workflows/tests.yml`) runs the test suite on every push/PR,
  with the 90% coverage gate applied to `tests/unit` only. No linter/
  formatter is configured yet — don't add one speculatively (ruff, black,
  pre-commit) unless asked, flag it as a suggestion instead.

## Commits & PRs

- Follow the global git-safety rules (no `--no-verify`, no force-push, no
  amending unless asked, confirm before anything destructive).
- Only commit when the user explicitly asks, per standard Claude Code
  behavior — this project has no CLAUDE.md override of that default.
